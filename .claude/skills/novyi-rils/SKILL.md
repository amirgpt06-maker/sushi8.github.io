# Новый рилс

## 0. Стиль каждого рилса — «Apple × кино» (решение пользователя)
* **Стиль «Apple» = стиль первых референсов пользователя (skill montazh), НЕ самодельные карточки.** Пользователь: «это не Apple;
  Apple — те, что я скидывал самыми первыми» (ролики с подписями-стопками). Поэтому весь текст рисует **движок montazh**
  (`engine/render.js` + `compose.py`): подпись-стопка (мелкое слово сверху слева, КЛЮЧЕВОЕ крупно, мелкое снизу справа, SF Pro,
  `fx: cinema` — из расфокуса), белые карточки-вспышки (`flash`), призыв `cta`, водяной знак `@ник` внизу. Свои рисованные
  карточки/маркеры не использовать. Ключевое слово — акцентом (`accent`, здесь синий `#4C8DFF`).
* **Цветовая гамма: белый и синий в приоритете.** Вспышки белые с тёмно-синим текстом, акцент синий, кино-грейд холодный
  (синие тени), без жёлтого и оранжевого.
* **Монтаж:** кино-планы из стока (холодный грейд, лёгкое зерно, мягкий наезд) + вспышки; у фразы `"look": "kino"|"flash"|"title"`
  (по умолчанию каждая третья фраза — вспышка). Планы 1.2–2 с, вжух на каждой склейке, наплыв 0.25 с.
* **Люди:** только силуэты и руки, **женщин нет вообще**, лиц нет (детектор лиц + `stock/blocked.txt`).
* **Музыки нет.** Звуки — из пака пользователя (последняя папка со звуками → `engine/sfx_local`, роли `sc_whoosh`, `wbpop`/`tagpop`, `tink`, `aplkey`),
  слышные: −6…−9 дБ к голосу. Фон — **нашиды из `nashid/` как есть (без блюра и обработки)**, только тихо: **громкость «1 из 100» = 1 % от голоса (−40 дБ)**; в 0 с тишины, за первую секунду плавно до уровня, в последнюю секунду плавно до нуля (стык зацикленного рилса не слышен), по одному на рилс по очереди,
* **Хук + удержание + призыв.** `hook` в сценарии — 3–6 слов на экране с 0-й секунды («Нейросеть отвечает как учебник?»), в речи —
  та же боль. На ~8–10 с — «открытая петля» («сейчас покажу, что меняет всё») и смена картинки/карточка; в последней трети — результат.
  Последняя фраза — призыв «подпишись» + **цель: подписчики в Instagram и Telegram** — карточка с `@saidulaev.ai` и Telegram-каналом
  (`brand.json`: `ig`, `tg`; пока `tg` пуст — карточки Telegram нет). В посте — кодовое слово: «напиши ПРОМПТ — пришлю в личку».
* **Ключевые слова → ссылка.** `keywords.json`: слово → текст + ссылка. Бот в Telegram отвечает подписчику (`telegram.py check`,
  строки `KEYWORD`); незнакомый вопрос приходит строкой `QUESTION <chat> <msg> <текст>` — отвечаю сам коротко, по делу, голосом
  блога (`telegram.py answer <chat> <msg> "текст"`). Мгновенных ответов нет: проверка идёт по расписанию. Автоответ в личку
  Instagram — только через Meta API или ManyChat (бесплатный тариф): не подключено.

## 0б. Рилсы БЕЗ голоса и без лица — Урок 5 (решение пользователя: «чистый трафик», верх воронки)
Главная мысль: убирает отмазку «боюсь показать лицо / не умею говорить на камеру». Цепляет **ударный заголовок**, а не лицо и голос.
Подходит и когда пользователь не может записать голос. Те же правила стиля: без женщин и лиц (силуэты, природа, архитектура, руки),
без музыки, звуки пака, фон — размытые нашиды (слов не разобрать), гамма белый + синий.

**Ударный заголовок** (1 фраза, несколько слов) — задаёт вопрос или конфликт, бьёт в боль/любопытство, мозг не может пролистать:
«Почему нейросеть отвечает как учебник», «Слова, которые нельзя писать в ChatGPT», «Как получить глубокие ответы от Claude»,
«Что будет, если ИИ ответит вместо тебя». Работают: вопрос «почему…», запрет/опасность («нельзя»), страх «это только начало»,
«как выглядело до / как сейчас». **Заголовок честный:** интрига обязана раскрываться в ролике; не пугать ложными фактами и
не выдумывать новости/чужие слова.

**Форматы без голоса (на выбор в `scenario.json`: `"format"`):**
1. `headline` — **фоновое видео + ударный заголовок + текст снизу.** Заголовок крупно сверху/по центру (стопка движка), под ним
   2–4 строки пояснения; фон — сток без людей (природа, город, архитектура, свет), фон меняется каждые 3–4 с (красивые места
   заходят хорошо). Длина 10–20 с, текст читается 2.5–3 слова/с.
2. `titles` — **титры по ходу «видео-рассказа»**: вся история идёт титрами поверх смены кадров (не под описанием); глубокий смысл,
   хук в первые 3 с, боль, развязка. Длина 25–40 с. Нашид — размытый фон. Кадры меняются, чтобы выглядело как большое видео.
3. `carousel` — **карусель в рилсе:** слайд за слайдом раскрывает тему (заголовок-слайд, 3–6 слайдов с одной мыслью, финальный
   слайд-призыв); люди листают, репостят, сохраняют — Instagram считает рилс интересным. Темы-списки: «5 приёмов…», «слова, которые
   нельзя писать нейросети».
Призыв во всех форматах — на экране: слово из `keywords.json` или «ссылка в шапке», Instagram и Telegram.

**Стратегия аккаунта (из урока, учитывать в темах и постах):**
* Порядок: сначала 1–3 сильных **интересных** рилса (чтобы Instagram счёл автора интересным и начал показывать остальные), потом
  **полезные**; в «продающие» не уходить, пока аккаунт мал. Не «я заработал N / ученики заработали» — сейчас не работает;
  аккаунт = посадочная страница с пользой («медийная платформа»), долгая стратегия.
* Шапка профиля оформлена, у пользователя — **мета-галочка** (Meta Verified): помогает продвижению рилсов (напомнить пользователю).
* Рилс — верх воронки: трафик → прогрев → продажа (воронку разбирать отдельно). Ожиданий от каждого рилса нет; не залетело — не страшно.
* Конкуренция высокая: заголовок и тема важнее монтажа.
Реализация без голоса (`make_reel.py --silent`: тайминг по скорости чтения, без озвучки и расшифровки) — в работе, пока пишу сценарий и собираю вручную.

## 0в. Тексты: простые и продающие — Урок 6 (для сценария, подписи к посту, ответов подписчикам)
Онлайн читают в ленте за 2 секунды, а не как книгу. Цель текста — чтобы дочитали и сделали **одно** действие. «Красиво» ≠ «продаёт».

**5 принципов:**
1. **Читабельность:** предложения 10–15 слов (максимум 20), абзацы 2–3 строки, воздух между абзацами; без канцелярита, «в современных
   реалиях», причастных оборотов. Убирать вводные «на самом деле», «как бы», «в принципе», «короче говоря».
2. **Динамика:** чередовать длину (коротко — длинно — коротко), однострочные абзацы для акцента, вопросы читателю, прямая речь.
3. **Понятность:** термины объяснять простыми словами («лид-магнит — бесплатный материал, который привлекает людей»); писать
   как другу за чаем; **правило бабушки** — не поймёт, перепиши. Слова подбирать под аудиторию (экспертам — «оффер», широкой — «предложение»).
   Простота не делает автора глупее — это умение говорить с платформой.
4. **Триггеры естественно:** срочность и дефицит — только настоящие и в нужный момент (закрытие продаж), в обычных постах не давить
   («купи сейчас, осталось два места»). Хорошо: честная причина ограничения («беру 10 человек, физически больше не успею»).
   **Выдуманный дефицит, ложные дедлайны и «осталось 2 места», если это неправда, — не писать.**
5. **Одно чёткое целевое действие в конце:** реакция, комментарий (номер/слово), ссылка, заявка, покупка — **одно**, не три сразу.

**Формула продающего текста (пост / сценарий):**
1. **Хук** (1–2 строки): вопрос, провокация, цифры («3 ошибки…»), личная история, проблема. Если все вокруг так начинают — изменить
   (баннерная слепота).
2. **Суть + усиление боли и запроса:** в чём проблема читателя → усилить; что он хочет → усилить («представь…»).
3. **Раскрытие через личную историю или метафору** (прогрев — как знакомство: сначала узнать друг друга, потом дружить). Истории
   только **настоящие** и от лица автора; опыт и цифры автора (годы, проекты, кейсы учеников) брать только те, что он сообщил, —
   **не выдумывать цифры и чужие результаты**.
4. **Доказательства:** опыт, цифры, кейсы (с разрешения учеников).
5. **Итог — призыв** (одно действие).

**Проверка перед публикацией:** прочитать вслух как другу; правило бабушки; вычеркнуть вводные слова; одно действие в конце; нет
выдуманных цифр и ложного дефицита. **Прогрев перед оффером:** сначала доверие и польза, потом продажа; продающие посты — серией
(история → боль/возражения → оффер), сторителлинг от первого лица. Для аккаунта пользователя (блог про нейросети) — пока польза,
продавать не спешить (см. стратегию в 0б).

## 1. Сценарий (пишу сам) — по формуле «Урок 4: вирусный контент, который приводит покупателей»
Тема — из запроса или **первая строка `topics.txt`** без пометки `✓` (после сборки поставить `✓ <дата>` в начале строки).
Тип рилса — пометка в начале строки темы: `[И]` интересный, `[П]` полезный, `[Пр]` продающий. Без пометки — по очереди И → П → И → П,
продающий — раз в 4–5 рилсов или когда есть что продавать.

**Принцип.** Вирусность — не клоунада и не кривляние. Вирусный рилс — тот, где человек думает «это про меня» (резонанс),
репостит и задумывается. Рилс — верх воронки: **охват → подписка → прогрев → продажа**, поэтому в конце — конкретный шаг
(ключевое слово или шапка профиля). От каждого рилса не ждём вирусности: одна программа из интересных, полезных и продающих.

**Структура (порядок обязателен), 5 блоков на 30–40 с:**
1. **Хук-загадка (1–3 с)** — заставляет задуматься: интрига, «над этим смеялись, а потом…», неожиданный контраст.
   Пример для блога про ИИ: «Надо мной смеялись, что я пишу тексты нейросетью. А потом я закрыл клиентов на 200 тысяч».
2. **Личное доказательство** — кто ты: **только то, что пользователь сам сообщил** (у него нет цифр и кейсов — их не выдумывать). Без цифр: доказательство = честный опыт простыми словами («я каждый день работаю с нейросетями и вижу, где все спотыкаются») или конкретный пример из практики, который он рассказал.
3. **Якорь ценностей** — во что веришь: «Нейросеть — инструмент, а не волшебная кнопка» (1 фраза, своя философия блога: простыми словами,
   без хайпа, польза). По ценностям человек понимает «мой/не мой».
4. **Механика доверия — польза** — почему работает: кусок системы, который можно применить сразу (приём, шаблон промпта, шаги).
5. **Призыв к конкретному действию** — «Напиши слово ПРОМПТ — пришлю шаблон» или «ссылка в шапке профиля», затем «подпишись»
   (Instagram и Telegram). Слово = запись в `keywords.json`. **Ключевое слово выбираю сам по теме видео** (одно слово капсом, по смыслу: ПРОМПТ, ПРЕЗЕНТАЦИЯ, РЕЗЮМЕ…) и сам пишу материал, который бот отправит подписчику **текстом** (ссылок нет, шаблон/чек-лист/промпт прямо в сообщении). Новую запись добавляю в `keywords.json` в том же запуске, что и сценарий.

**Типы:**
* **[И] интересный** — растит аккаунт: резонанс, история, твист, «про меня» (упор на блоки 1–3, польза короче).
* **[П] полезный** — экспертность и доверие: блок 4 на 60 % ролика.
* **[Пр] продающий** — прямая продажа (курс, закрытый канал, услуга): блоки 4–5, оффер и цена/условия — только те, что дал пользователь.
Не клоунада: без кривляния, чужих драм и тем, унижающих достоинство; тон ровный, уважительный.

Пишу `scenario.json` (пример — `.claude/skills/novyi-rils/example.json`):
* **30–40 с речи ≈ 75–100 слов**, 6–9 фраз. Живой разговорный язык, на «ты», предложения до 10–15 слов, без канцелярита (см. 0в).
* В `scenario.json` поле `"type"` (`И`/`П`/`Пр`) и `"formula"`: номер блока для каждой фразы (1–5) — для проверки.
* Текст фраз = как произносить (числа словами, без эмодзи, «ИИ» писать «И-И» если голос коверкает).
* У каждой фразы: `stock` — 2–4 английских тега для стока (смотреть `stock/catalog.json`), `keywords` — 1–2 главных слова для стопки.
* `hook` — 3–6 слов хука на экране. `post` — 2–4 предложения + призыв с ключевым словом; `hashtags` — 6–10.
* Перед отправкой проверить: все 5 блоков на месте, в первые 3 с есть загадка, в конце — конкретное слово/действие, нет выдуманных цифр.

## 2. Голос — свой, бесплатно (решение пользователя: без платных озвучек)
`scripts/telegram.py script scenario.json` — бот присылает сценарий; пользователь записывает голосовое (можно своими словами)
и отвечает на сообщение. `scripts/telegram.py check` скачивает запись (`VOICE <файл> <scenario>`).
Синтез (`--engine piper`) — только чтобы проверить систему; ElevenLabs в `tts.py` оставлен на будущее, не использовать без просьбы.

## 3. Сборка
```
/root/venv-video/bin/python .claude/skills/novyi-rils/scripts/make_reel.py scenario.json --voice <запись>
```
* Голос: паузы в начале и в конце срезаются, обработка `video-tools/voice_pro.py --amount 0.3` (одобренный вариант), итог −14 LUFS.
* Субтитры — **строго по тому, что сказано в записи** (faster-whisper, ru, по словам), по 1–3 слова, ключевые слова сценария
  жёлтым. Сказанное привязывается к фразам сценария — от них берётся сток.
* Сток: Mixkit по `stock/catalog.json` (теги фразы → лучший клип без повторов), планы по 2–3 с, мягкий наезд, наплыв 0.25 с.
  **Без лиц**: в каждом новом клипе детектор лиц (YuNet, `models/yunet.onnx`) смотрит 5 кадров — с лицами клип уходит в
  `stock/blocked.txt`; люди по названию отсекаются (кроме рук). Без музыки.
* Звуки: из `sfx/` (`whoosh`, `pop`, `ding`), иначе синтез из skill montazh.
* Результат: `ready/<дата>/<slug>/reel.mp4`, `post.txt` (текст + хэштеги), `cover.jpg`, `scenario.json`, `status.json`.

## 4. Проверка перед отправкой (обязательно)
Сделать лист кадров (каждые 2 с) и посмотреть: **нет крупных лиц и нет женщин в кадре** (правило пользователя) — такие id
добавить в `stock/blocked.txt` и пересобрать; субтитры читаются; сток подходит к фразам; громкость −14 LUFS.

## 5. Telegram и публикация
* `scripts/telegram.py send ready/<дата>/<slug>` — рилс + пост в бот на проверку (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` в `.env`).
* `scripts/telegram.py check` — ответы пользователя: «ок» → `status.json: approved`; другой текст → правки (`changes`,
  `comments`) — переделать по ним и отправить снова. **Публиковать только после «ок».** Публикация в Instagram API — позже.

## 6. Ежедневный запуск (18:00 МСК)
18:00 — тема из `topics.txt` → сценарий → `telegram.py script` → пометить тему `✓`. Проверки ответов (каждый час днём):
`telegram.py check` → пришло голосовое — сборка → проверка кадров → `telegram.py send`; «ок» — одобрено; текст — правки. Папки `ready/`, `stock/*.mp4`, `.env` в git не попадают.

## 7. Публикация и комментарии в Instagram (официальный API, бесплатно; `scripts/instagram.py`)
* **Публикую сам, но только одобренный рилс** (владелец ответил «ок» в Telegram): `instagram.py publish ready/<дата>/<slug>` —
  видео, обложка (кадр на 1.6 с), текст поста и хэштеги из `post.txt`. Без «ок» скрипт отказывается публиковать.
* **Комментарии:** `instagram.py comments` — ключевое слово из `keywords.json` → публичный ответ «отправил в личные» + материал в
  личку (private reply); остальные — строка `COMMENT_QUESTION <id> <ник> <текст>`: отвечаю сам коротко и честно
  (`instagram.py reply <id> "текст"`), без выдуманных фактов, личных данных в репозиторий не пишу.
* Нужны переменные окружения `INSTAGRAM_ACCESS_TOKEN` и `INSTAGRAM_USER_ID` (у пользователя профессиональный аккаунт, приложение Meta).
  Без них публикация/комментарии не работают; Telegram-часть не зависит от этого.
* Ограничения Instagram: личный ответ на комментарий — в течение 7 дней; лимит публикаций через API — 100 в сутки; аккаунт должен
  быть Business/Creator и привязан к странице Facebook. Скрипт написан по документации Meta, на боевом аккаунте ещё не проверялся.

## 8. Ежедневная работа без записи в git (важно)
Запуски по расписанию стартуют **без права записи в репозиторий** (git push даёт 403) — поэтому:
* Сценарии заготавливаются заранее и лежат в `scenarios/pool/*.json` (по формуле Урока 4; у каждого `keyword`, `hook`, `post`, `hashtags`);
  ключевые слова с материалами — в `keywords.json`. Новые сценарии и слова добавляю в обычных сессиях (когда пул кончается).
* Состояние хранит Telegram: сценарий уходит документом `scenario.json`, голосовое владельца — ответом на него (сценарий берётся из
  документа); необработанные сообщения подтверждаются через offset. Папки `ready/` живут только в рамках одного запуска.
* Запуск: `telegram.py check` → строки `VOICE <голос> <сценарий>` → `make_reel.py <сценарий> --voice <голос>` → лист кадров →
  `telegram.py send ready/<…>`; при сбое — `telegram.py notify "…"` (владелец пришлёт голос заново); `APPROVED`/`EDIT` — пока только ответ;
  `QUESTION` — отвечаю `telegram.py answer`. В 17:51 дополнительно `telegram.py daily` (сценарий дня по дате).
* Публикация в Instagram (`instagram.py`) — после подключения токена; рилс одобрен позже, чем собран, поэтому публиковать надо из
  того же запуска или пересобирать — решить при подключении.
